# 5.2 Entity Mappings & Relationships

[← Back to Chapter 5: Spring Data JPA, Hibernate & Database](./index.md)

Modeling relational associations in Java requires defining association multiplicity, ownership sides, cascading rules, and fetching strategies.

---

## 1. Core Mapping Annotations

```java
@Entity
@Table(name = "customers", indexes = {
    @Index(name = "idx_customer_email", columnList = "email", unique = true)
})
public class Customer {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 100)
    private String fullName;

    @Column(nullable = false, unique = true, length = 150)
    private String email;

    @CreationTimestamp
    @Column(updatable = false)
    private Instant createdAt;

    @UpdateTimestamp
    private Instant updatedAt;
}
```

## 2. Association Multiplicities & Ownership

### The Rule of Ownership:
The entity containing the **Foreign Key** in the database table is the **Owner Side**. The non-owning side must use `mappedBy`.

### One-to-Many / Many-to-One (Bidirectional Best Practice)

```java
// Non-owning side (Parent)
@Entity
public class Department {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;

    // mappedBy points to the field name on Employee!
    @OneToMany(mappedBy = "department", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Employee> employees = new ArrayList<>();

    // Mandatory helper methods to keep bidirectional state in sync in memory!
    public void addEmployee(Employee emp) {
        employees.add(emp);
        emp.setDepartment(this);
    }

    public void removeEmployee(Employee emp) {
        employees.remove(emp);
        emp.setDepartment(null);
    }
}

// Owning side (Child, holds foreign key)
@Entity
public class Employee {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;

    @ManyToOne(fetch = FetchType.LAZY) // Always LAZY!
    @JoinColumn(name = "department_id", nullable = false)
    private Department department;
}
```

---

## 3. FetchType: LAZY vs EAGER

- **`FetchType.LAZY` (Recommended Default)**: Related entities are loaded on demand when the getter is accessed.
- **`FetchType.EAGER` (Dangerous in Production)**: Automatically joins or executes extra queries immediately.

> **Crucial Rule**: JPA defaults `@ManyToOne` and `@OneToOne` to `FetchType.EAGER`. **Always explicitly override them to `FetchType.LAZY`** to prevent catastrophic accidental table queries across your entire database graph!
