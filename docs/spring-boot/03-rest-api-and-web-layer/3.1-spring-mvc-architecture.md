# 3.1 Spring MVC Architecture & Request Flow

[← Back to Chapter 3: REST API & Web Layer](./index.md)

Spring MVC implements the **Front Controller pattern** via `DispatcherServlet`. Every inbound HTTP request travels through a refined pipeline of handlers, interceptors, and adapters before returning a serialized response to the client.

---

## 1. End-to-End Request Processing Flow

```
[ Client Browser / Mobile App ]
              │ HTTP Request
              ▼
    [ Filter Chain (Security, CORS, Logging) ]
              │
              ▼
   ┌─────────────────────────────────────────┐
   │         DispatcherServlet               │
   │         (The Front Controller)          │
   └───────┬───────────────────▲─────────────┘
           │ 1. Find Handler   │ 2. HandlerExecutionChain
           ▼                   │    (Handler + Interceptors)
   ┌───────────────────────────┴─────────────┐
   │             HandlerMapping              │
   │ (RequestMappingHandlerMapping)          │
   └─────────────────────────────────────────┘
           │
           │ 3. Execute Handler
           ▼
   ┌─────────────────────────────────────────┐
   │             HandlerAdapter              │
   │ (RequestMappingHandlerAdapter)          │
   └───────┬───────────────────▲─────────────┘
           │ Invokes method    │ Returns Object or ModelAndView
           ▼                   │
   ┌───────────────────────────┴─────────────┐
   │            @RestController              │
   │         (Your Business Code)            │
   └─────────────────────────────────────────┘
           │
           │ 4. If REST (@ResponseBody):
           ▼
   ┌─────────────────────────────────────────┐
   │          HttpMessageConverter           │
   │ (MappingJackson2HttpMessageConverter)   │
   └─────────────────────────────────────────┘
              │ Serialized JSON
              ▼
    [ HTTP Response 200 OK to Client ]
```

---

## 2. Core Architectural Components

1. **`DispatcherServlet`**: Central front controller registered with the servlet container. Coordinates all request flow.
2. **`HandlerMapping`**: Examines request URL, HTTP method, and headers to locate the corresponding controller method.
3. **`HandlerExecutionChain`**: Wraps the matched controller method along with all applicable `HandlerInterceptor` instances.
4. **`HandlerAdapter`**: Abstracts controller method execution; resolves method arguments (e.g., extracting `@PathVariable`, deserializing `@RequestBody`).
5. **`HttpMessageConverter`**: Serializes Java return objects into JSON/XML (e.g., Jackson) or deserializes inbound payloads.

---

## 3. Filters vs HandlerInterceptors

A classic senior engineering interview comparison:

| Characteristic | Servlet Filter (`Filter`) | Spring Interceptor (`HandlerInterceptor`) |
| :--- | :--- | :--- |
| **Specification** | Standard Java EE / Jakarta Servlet API | Spring MVC proprietary framework |
| **Execution Point** | Outside `DispatcherServlet` (lowest level) | Inside `DispatcherServlet`, around controller execution |
| **Awareness** | Knows only `ServletRequest` & `ServletResponse` | Knows the target handler (`HandlerMethod`) and model |
| **Common Use Cases**| Low-level security, CORS, GZIP compression, raw payload caching | Auth validation, request audit logs, performance timing, tenant switching |
