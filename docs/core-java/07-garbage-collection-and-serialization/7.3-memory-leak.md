# 8.3 Object Reachability: Strong, Soft, Weak & Phantom References

[← Back to Chapter 8: Garbage Collection & Serialization](./index.md)

Java's `java.lang.ref` package enables developers to interact with the Garbage Collector's lifecycle decisions through reference strengths.

---

## 1. Reference Strength Hierarchy

```
  [ Strong Reference ]  (e.g., Object obj = new Object();)
           │
           ▼ (Decreasing Reference Strength)
  [ Soft Reference ]    (SoftReference<T>: Collected only right before OutOfMemoryError)
           │
           ▼
  [ Weak Reference ]    (WeakReference<T>: Collected on the very next GC cycle)
           │
           ▼
  [ Phantom Reference ] (PhantomReference<T>: get() always returns null; post-mortem cleanup)
```

---

## 2. Real-World Architectural Use Cases

### SoftReference: Memory-Sensitive In-Memory Caches
```java
SoftReference<byte[]> imageCache = new SoftReference<>(loadImageBytes());
byte[] bytes = imageCache.get();
if (bytes == null) {
    // GC cleared the cache under high memory pressure; re-fetch from disk/network
    bytes = loadImageBytes();
    imageCache = new SoftReference<>(bytes);
}
```

### WeakReference: `WeakHashMap` & Metadata Registries
- Used when you want key-value associations where the entry automatically disappears from the map when the key object is no longer referenced anywhere else in the application.

### PhantomReference & `java.lang.ref.Cleaner`
- `finalize()` was deprecated in Java 9 and removed in modern Java due to performance and security vulnerabilities.
- `Cleaner` works with `PhantomReference` to safely release native C/C++ memory pointers, GPU buffers, or raw OS sockets when objects are reclaimed.
