# 8.4 Serialization Fundamentals & the serialVersionUID Contract

[← Back to Chapter 8: Garbage Collection & Serialization](./index.md)

**Serialization** transforms an in-memory Java object graph into a flat sequence of binary bytes for disk persistence or transmission over a network socket. **Deserialization** reconstructs that live object graph from the byte stream.

---

## 1. The `Serializable` Marker Interface

`java.io.Serializable` is a marker interface containing no methods. It signals to the JVM reflection subsystem that the class permits binary state extraction:

```java
import java.io.*;

public class UserSession implements Serializable {
    private static final long serialVersionUID = 1L; // Explicit version UID

    private String userId;
    private String role;

    // Constructors, Getters, Setters
}
```

---

## 2. Writing and Reading Streams

```java
// Serialization
try (var oos = new ObjectOutputStream(new FileOutputStream("session.ser"))) {
    oos.writeObject(new UserSession("user_101", "ADMIN"));
}

// Deserialization
try (var ois = new ObjectInputStream(new FileInputStream("session.ser"))) {
    UserSession session = (UserSession) ois.readObject();
}
```

---

## 3. The `serialVersionUID` Contract

If a class does not declare an explicit `serialVersionUID`:
- The JVM compiler calculates a 64-bit hash at compile-time based on method signatures, field names, and interfaces.
- If you add a single field or refactor a method later, the compiler recalculates a new hash.
- Deserializing previously saved data throws `java.io.InvalidClassException: local class incompatible`!
- **Best Practice**: Always explicitly declare `private static final long serialVersionUID = 1L;`.
