# 3.3 String Equality & .intern() Mechanics

[← Back to Chapter 3: Strings in Java](./index.md)

Comparing strings is one of the most common sources of logic bugs in Java applications.

---

## 1. `==` vs `.equals()` vs `.compareTo()`

- `==`: Compares **reference identity** (do both pointers point to the exact same Heap memory address?).
- `.equals(Object)`: Compares **character sequence content** (checks lengths and compares bytes/chars).
- `.compareTo(String)`: Compares **lexicographical ordering** (returns negative, zero, or positive integer for sorting).

```java
String a = "hello";
String b = new String("hello");

System.out.println(a == b);      // false (Different Heap memory locations)
System.out.println(a.equals(b)); // true  (Same characters: h-e-l-l-o)
```

:::tip Defensive String Comparison
To prevent `NullPointerException`, invoke `.equals()` from a known non-null constant:
```java
// BAD: Throws NPE if role is null!
if (role.equals("ADMIN")) { ... }

// GOOD: Completely NPE-safe!
if ("ADMIN".equals(role)) { ... }
```
:::

---

## 2. Compile-Time Literal Folding

The Java compiler folds constant string literals at compile-time:

```java
String s1 = "HelloWorld";
String s2 = "Hello" + "World"; // Computed at compile-time by javac!
System.out.println(s1 == s2);  // true! Both point to the same SCP literal

String prefix = "Hello";
String s3 = prefix + "World";  // Non-constant variable expression! Evaluated at runtime
System.out.println(s1 == s3);  // false!
```

---

## 3. The `.intern()` Method

Calling `str.intern()` queries the String Constant Pool:
- If the pool already contains a string equal to `str`, the pool reference is returned.
- If not, `str` is added to the pool and its reference is returned.

```java
String heapStr = new String("Spring");
String interned = heapStr.intern();
String literal = "Spring";

System.out.println(heapStr == literal);  // false
System.out.println(interned == literal); // true
```
