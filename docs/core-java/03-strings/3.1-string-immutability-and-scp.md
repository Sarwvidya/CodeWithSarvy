# 3.1 String Immutability & the String Constant Pool

[← Back to Chapter 3: Strings in Java](./index.md)

In Java, instances of `java.lang.String` are strictly **immutable**. Once created, their character sequence cannot be altered in memory.

---

## 1. Why is String Immutable in Java?

James Gosling, creator of Java, designed String immutability for 4 foundational reasons:

1. **The String Constant Pool (SCP)**: Allows thousands of identical string literals throughout an application to share a single Heap allocation, saving megabytes of RAM.
2. **Security**: Strings carry sensitive credentials, URLs, database connection strings, and file paths. If mutable, an attacker could alter a path after security validation checks passed.
3. **Thread Safety**: Immutable objects are inherently thread-safe without needing locks (`synchronized`). Multiple threads can read string instances concurrently with zero race conditions.
4. **HashCode Caching**: The hash code of a String is computed lazily and cached inside the object (`private int hash`). It is guaranteed never to change, making String the optimal key for `HashMap` and `HashSet`.

---

## 2. The String Constant Pool (SCP) Architecture

The SCP is a special hash table maintained directly in the **JVM Heap** (relocated from PermGen in Java 7+):

```java
String s1 = "Java";               // Allocated in String Constant Pool
String s2 = "Java";               // Reuses the identical pool reference!
String s3 = new String("Java");   // Creates a separate Object in general Heap!
```

```
          JVM Heap Space
┌───────────────────────────────────────────────────────────┐
│  String Constant Pool (SCP)                               │
│  ┌─────────────────────────────────┐                      │
│  │ "Java" (Address: @0x100)        │◄─── s1 & s2          │
│  └─────────────────────────────────┘                      │
│                                                           │
│  General Heap                                             │
│  ┌─────────────────────────────────┐                      │
│  │ new String instance (@0x200)    │◄─── s3               │
│  │ (internal char/byte[] -> @0x100)│                      │
│  └─────────────────────────────────┘                      │
└───────────────────────────────────────────────────────────┘
```

Resulting checks:
```java
System.out.println(s1 == s2);      // true  (Same pool address)
System.out.println(s1 == s3);      // false (Different heap address)
System.out.println(s1.equals(s3)); // true  (Identical content)
```
