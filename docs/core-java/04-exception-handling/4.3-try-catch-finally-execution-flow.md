# 4.3 try-catch-finally Execution Flow

[← Back to Chapter 4: Exception Handling](./index.md)

The `try-catch-finally` block is Java's foundational error handling construct. Understanding its detailed control flow guarantees that critical resources are never orphaned.

---

## 1. Execution Flow Rules

1. **`try` block**: Houses code that might throw an exception.
2. **`catch` block**: Executes only if an exception matching the parameter type is thrown. Multiple catch blocks must be ordered from **most specific subclass to most general superclass**.
3. **`finally` block**: **Always executes**, whether an exception occurred, was caught, or was uncaught.

```java
try {
    processPayment();
} catch (InsufficientFundsException | ExpiredCardException e) {
    // Multi-catch (Java 7+): parameter 'e' is implicitly final
    log.warn("Payment failed: {}", e.getMessage());
} catch (PaymentGatewayException e) {
    // Broader exception caught lower in the hierarchy
    log.error("Gateway outage", e);
} finally {
    releaseTransactionLock(); // Guaranteed cleanup!
}
```

---

## 2. Return Precedence Gotcha in `finally`

If both `try`/`catch` and `finally` have return statements, the return value in `finally` **overrides everything**:

```java
public static int testReturn() {
    try {
        return 10;
    } finally {
        return 20; // OVERWRITES return value of 10!
    }
}
// Calling testReturn() returns 20!
```

:::danger Never Return from a Finally Block
Returning or throwing exceptions from a `finally` block swallows any prior exception thrown in the `try` block, destroying debugging stack traces.
:::

---

## 3. When Will `finally` NOT Execute?

There are only three scenarios where a `finally` block fails to execute:
1. `System.exit(status)` is called.
2. Fatal JVM crash (e.g. fatal segmentation fault or power cut).
3. Infinite loop or deadlock occurring inside the `try` or `catch` block.
