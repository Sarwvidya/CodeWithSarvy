# 8.1 Garbage Collection Fundamentals & Generational Hypothesis

[← Back to Chapter 8: Garbage Collection & Serialization](./index.md)

Garbage Collection (GC) in Java is an automatic memory management process that identifies and reclaims heap memory allocated to objects that are no longer reachable by any live thread.

---

## 1. The Weak Generational Hypothesis

Decades of runtime profiling across millions of production applications confirmed two empirical truths:
1. **Most objects die shortly after instantiation** (e.g. local loop variables, temporary DTOs, HTTP request contexts).
2. **References from older objects to younger objects are extraordinarily rare.**

```
┌───────────────────────────────────────────┬───────────────────────────────────────────┐
│              Young Generation             │              Old Generation               │
│                                           │                 (Tenured)                 │
│ ┌──────────────────────┬─────────┬──────┐ │ ┌───────────────────────────────────────┐ │
│ │ Eden Space           │ S0      │ S1   │ │ │ Long-lived survived objects           │ │
│ │ (Fresh allocations)  │ Survivor│      │ │ │ (Promoted after threshold, e.g. 15)   │ │
│ └──────────────────────┴─────────┴──────┘ │ └───────────────────────────────────────┘ │
└───────────────────────────────────────────┴───────────────────────────────────────────┘
```

---

## 2. The Core GC Phases

1. **Mark**: Traverse the object reference graph starting from **GC Roots** (Active thread stacks, static variables, JNI global references). Any reachable object is marked alive.
2. **Sweep**: Identify contiguous memory blocks occupied by unreferenced/dead objects and return those addresses to the JVM free list.
3. **Compact**: Shift surviving live objects to the beginning of the memory space, eliminating memory fragmentation and enabling lightning-fast **bump-the-pointer** allocation.

---

## 3. GC Stop-The-World (STW) Pauses

During critical phases (like initial marking and live object relocation), the JVM must bring all application mutator threads to a **Safepoint**. Modern GC algorithms (G1, ZGC) optimize to make these pauses concurrent or sub-millisecond.
