# 6.7 Concurrent & Thread-Safe Collections

[← Back to Chapter 6: Multithreading & Concurrency](./index.md)

Standard collections in `java.util` (such as `ArrayList`, `HashMap`, and `HashSet`) are intentionally non-thread-safe to maximize single-threaded performance. Under concurrent access with at least one writer thread, standard collections exhibit data corruption, lost updates, infinite loops, and `ConcurrentModificationException`.

---

## 1. The Problem with Standard Collections Under Concurrency

```
Thread A: list.add("Item 1") ────┐
                                 ├──► Internal Array: [ elementData ] (size=1)
Thread B: list.add("Item 2") ────┘
```

When two threads concurrently invoke `.add()` on a standard `ArrayList`:
1. Both read `size = 1`.
2. Both write to index `elementData[1]`, overwriting each other's data (**lost update**).
3. Both increment `size`, leaving `elementData[2]` null while reporting `size = 3`.
4. Reading or iterating concurrently causes **`ConcurrentModificationException`** via fail-fast iterator checks (`modCount != expectedModCount`).

---

## 2. Legacy Synchronized Collections (`java.util`)

Prior to Java 5, thread-safety was achieved via class-level synchronization or synchronized wrappers.

### 2.1 `Vector` and `Hashtable` (Legacy)
- Every single method is decorated with `synchronized`.
- **Major Bottleneck**: Coarse-grained monitor lock on `this`. While one thread reads, all other threads (readers and writers) are blocked.
- Considered legacy; not recommended in modern applications.

### 2.2 `Collections.synchronizedList()` & `Collections.synchronizedMap()`
Synchronized wrappers wrap standard collections inside a synchronized decorator:

```java
List<String> syncList = Collections.synchronizedList(new ArrayList<>());
Map<String, Integer> syncMap = Collections.synchronizedMap(new HashMap<>());
```

- **Lock Scope**: Synchronizes on an internal `mutex` object across every operation.
- **Critical Caveat**: Iteration must still be **manually synchronized** by the caller!
  ```java
  // Must synchronize explicitly on the collection wrapper during iteration
  synchronized (syncList) {
      for (String item : syncList) {
          System.out.println(item);
      }
  }
  ```

## 3. Modern Concurrent Collections (`java.util.concurrent`)

Introduced in `java.util.concurrent` (JSR-166), modern concurrent collections use **fine-grained locking**, **lock-free CAS (Compare-And-Swap)**, and **volatile memory barriers** to allow high concurrent throughput without coarse locks.

### 3.1 `ConcurrentHashMap`

`ConcurrentHashMap` is the industry standard for concurrent key-value storage.

```
                  ConcurrentHashMap Internal Architecture (Java 8+)
   Bucket Array:
   [ 0 ] ──► Node -> Node -> Node (Lock bucket head using synchronized)
   [ 1 ] ──► Empty (Insert new node via lock-free CAS)
   [ 2 ] ──► TreeBin (Red-Black Tree for hash collisions > 8)
   [ 3 ] ──► Node
```

- **Read Operations (`get`)**: Completely **lock-free**. Uses `volatile` reads on node values. Multiple threads read simultaneously without blocking.
- **Write Operations (`put`, `remove`)**:
  - If bucket is empty: Inserts the new node using **Lock-Free CAS**.
  - If bucket has nodes: Locks **only the first node (head)** of that specific bucket using `synchronized`. Other buckets remain accessible for concurrent writes!
- **Atomic Operations**:
  ```java
  ConcurrentMap<String, Integer> wordCounts = new ConcurrentHashMap<>();

  // Atomic compute if absent (no race condition between get and put)
  wordCounts.computeIfAbsent("Java", k -> 1);

  // Atomic increment
  wordCounts.compute("Java", (k, v) -> (v == null) ? 1 : v + 1);
  ```

## 4. Copy-On-Write Collections

### 4.1 `CopyOnWriteArrayList` & `CopyOnWriteArraySet`

Uses a copy-on-write strategy where any mutative operation (`add`, `set`, `remove`) creates a fresh cloned copy of the underlying array:

```
Read threads:  ──────► [ Original Array: "A", "B", "C" ] (Lock-free snapshot)
                              ▲
Write thread:  ──────► [ Cloned Array:   "A", "B", "C", "D" ] ──► Swaps reference
```

- **Read Operations**: Completely **lock-free and instantaneous**. Iterators operate on a snapshot that never throws `ConcurrentModificationException`.
- **Write Operations**: Expensive. Clones the entire internal array on every write.
- **Best Used For**:
  - Read-heavy, write-rare scenarios (e.g. event listener registries, service observers, configuration caches).

---

## 5. Concurrent Queues & Deques

Java provides specialized queues for high-performance multi-threaded producer-consumer patterns.

### 5.1 Blocking Queues (`BlockingQueue`)
Threads block when reading from an empty queue or writing to a full queue:

| Queue Implementation | Boundedness | Mechanism | Best Use Case |
| :--- | :--- | :--- | :--- |
| **`ArrayBlockingQueue`** | Bounded (fixed size) | Single lock + Condition variables | Predictable memory limit, worker pools |
| **`LinkedBlockingQueue`** | Optionally bounded | Dual locks (`takeLock` & `putLock`) | Independent producer & consumer throughput |
| **`PriorityBlockingQueue`** | Unbounded | Heap-ordered queue | Task prioritization by deadline/weight |
| **`SynchronousQueue`** | 0 capacity | Direct handoff | Thread pool direct handoff (`newCachedThreadPool`) |

### 5.2 Non-Blocking Lock-Free Queues (`ConcurrentLinkedQueue`)
- Unbounded queue based on the **Michael & Scott non-blocking queue algorithm**.
- Uses low-level CPU **CAS** primitives instead of lock monitors.
- Ideal when producers and consumers must not block each other under high load.

---

## 6. Sorted Concurrent Collections

Standard `TreeMap` and `TreeSet` are red-black trees that require complex tree rotations during balancing, making fine-grained locking impractical.

### 6.1 `ConcurrentSkipListMap` & `ConcurrentSkipListSet`
- Based on a probabilistic **Skip List** hierarchy.
- Provides thread-safe, logarithmic $O(\log N)$ search, insertion, and deletion without locking the entire tree.
- Keys are sorted in natural order or via custom `Comparator`.

---

## 7. Collection Selection Matrix

| Use Case / Requirement | Recommended Collection | Why? |
| :--- | :--- | :--- |
| High-throughput concurrent key-value store | `ConcurrentHashMap` | Bucket-level locking + lock-free volatile reads |
| Sorted concurrent key-value map | `ConcurrentSkipListMap` | Lock-free skip list with $O(\log N)$ ordered access |
| Read-heavy list (listeners, observers) | `CopyOnWriteArrayList` | Lock-free snapshot iteration; clone on write |
| Thread pool producer-consumer pipeline | `ArrayBlockingQueue` / `LinkedBlockingQueue` | Built-in backpressure with blocking `put()` / `take()` |
| Lock-free wait-free FIFO queue | `ConcurrentLinkedQueue` | CAS-based non-blocking queue |
| Concurrent unique element set | `ConcurrentHashMap.newKeySet()` | Backed by `ConcurrentHashMap` efficiency |
