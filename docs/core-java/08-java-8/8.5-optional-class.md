# 8.5 The Optional&lt;T&gt; Class & Null Safety

[← Back to Chapter 8: Java 8 Features](./index.md)

Introduced in Java 8, `java.util.Optional<T>` is a single-value container designed to explicitly represent the presence or absence of a value without resorting to error-prone `null` references.

---

## 1. Creating Optional Instances

```java
// 1. Definite non-null value (throws NPE immediately if value is null)
Optional<String> opt1 = Optional.of("CodeWithSarvy");

// 2. Value may or may not be null
Optional<String> opt2 = Optional.ofNullable(fetchNullableUsername());

// 3. Explicit empty container
Optional<String> opt3 = Optional.empty();
```

---

## 2. Functional Transformation Pipeline

Avoid checking `opt.isPresent()` and `opt.get()` like a traditional if-else block. Use the expressive functional fluent API:

```java
public String getUserCity(Long userId) {
    return userRepository.findById(userId)              // Optional<User>
            .map(User::getAddress)                       // Optional<Address>
            .map(Address::getCity)                       // Optional<String>
            .filter(city -> !city.isBlank())             // Still Optional<String>
            .orElse("Unknown City");                     // Fallback default string
}
```

---

## 3. `orElse()` vs `orElseGet()`: A Costly Trap

| Method | Behavior | Performance Impact |
| :--- | :--- | :--- |
| `orElse(T other)` | `other` expression is **always evaluated eagerly**, even when the Optional is present | High if `other` invokes database or network calls |
| `orElseGet(Supplier<? extends T> supplier)` | `supplier` is called **lazily only if** Optional is empty | Optimal: Zero overhead when value is present |

```java
// BAD: generateHeavyToken() is called EVERY SINGLE TIME, even if user already exists!
User user = optUser.orElse(generateHeavyToken());

// GOOD: generateHeavyToken() runs ONLY if optUser is empty!
User user = optUser.orElseGet(() -> generateHeavyToken());
```

---

## 4. Critical Anti-Patterns to Avoid

1. **Never use `Optional` as a method parameter**:
   ```java
   // ANTI-PATTERN: Forces caller to wrap nulls or primitives into Optional
   public void process(Optional<User> user) { ... }
   ```
2. **Never use `Optional` as a class field**: `Optional` does NOT implement `java.io.Serializable`, causing crashes in frameworks using Java serialization.
3. **Never call `.get()` without prior safety verification**: Calling `.get()` on an empty `Optional` throws `NoSuchElementException`.
