# 8.1 Lambda Expressions

[← Back to Chapter 8: Java 8 Features](./index.md)

Lambda expressions, introduced in Java 8, bring functional programming capabilities to Java. They provide a clear and concise way to represent single-method interfaces (Functional Interfaces) using an expression.

---

## 1. What is a Lambda Expression?

A **lambda expression** is an anonymous function—a function without a declared name, return type, or explicit access modifiers. It can be passed around as if it were an object and executed on demand.

```
(parameters) -> { expression or statements }
   ▲         ▲              ▲
   │         │              │
Argument   Lambda        Body / Logic
  List     Operator
```

---

## 2. Syntax Variations

Lambda syntax adapts dynamically depending on parameter count and statement complexity:

```java
// 1. Zero arguments
() -> System.out.println("Hello, Java 8!");

// 2. Single parameter (type inference allows omitting parentheses and type)
name -> System.out.println("Hello, " + name);

// 3. Multiple parameters with explicit types
(int a, int b) -> a + b;

// 4. Multiple parameters with inferred types (most common)
(a, b) -> a + b;

// 5. Multi-line body (requires curly braces and explicit return if returning a value)
(a, b) -> {
    int sum = a + b;
    System.out.println("Sum: " + sum);
    return sum;
};
```

---

## 3. Anonymous Inner Class vs Lambda Expression

Before Java 8, passing behavior required verbose anonymous inner classes:

### Legacy Anonymous Inner Class:
```java
Runnable r1 = new Runnable() {
    @Override
    public void run() {
        System.out.println("Thread running via Anonymous Class");
    }
};
```

### Modern Java 8 Lambda:
```java
Runnable r2 = () -> System.out.println("Thread running via Lambda");
```

| Aspect | Anonymous Inner Class | Lambda Expression |
| :--- | :--- | :--- |
| **Boilerplate** | High (class declaration, method signature) | Minimal (parameters and arrow body) |
| **Bytecode Generation** | Creates separate `.class` file (`Outer$1.class`) | Uses `invokedynamic` (no extra class file) |
| **`this` Keyword** | Refers to the inner class instance itself | Lexically scoped: refers to enclosing class |
| **Target** | Can implement interfaces or extend abstract/concrete classes | Can only implement Functional Interfaces |
| **Performance** | Higher memory footprint and classloader overhead | Lower memory footprint, faster startup |

## 4. Capturing Variables: Effectively Final Rule

Lambda expressions can access:
1. **Instance variables** and **static variables** (both readable and mutable).
2. **Local variables** from the enclosing scope, **provided they are final or effectively final**.

### Effectively Final Concept:
A local variable is *effectively final* if its value is never modified after initialization.

```java
int factor = 2; // Effectively final

List<Integer> numbers = List.of(1, 2, 3, 4);
numbers.forEach(n -> System.out.println(n * factor)); // Valid!

// BAD: Mutating variable breaks effectively final constraint
int counter = 0;
// numbers.forEach(n -> counter++); // COMPILE ERROR: Variable used in lambda must be final or effectively final
```

> **Why the restriction?** Local variables live on the stack and are destroyed when the enclosing method exits. Lambdas may execute asynchronously or outlive the stack frame, so the JVM creates a copy (closure capture). If the variable changed, the copies would fall out of sync.

## 5. Practical Examples

### Sorting a Collection:
```java
List<String> names = Arrays.asList("Charlie", "Alice", "Bob");

// Traditional:
// Collections.sort(names, new Comparator<String>() { ... });

// Lambda:
names.sort((s1, s2) -> s1.compareTo(s2));

// Even cleaner with Comparator method reference:
// names.sort(String::compareTo);
```
