# 8.4 Stream API

[← Back to Chapter 8: Java 8 Features](./index.md)

The **Stream API** (`java.util.stream`) represents a powerful, declarative mechanism for processing sequences of elements. Instead of writing explicit loops with conditional logic, you define high-level transformation pipelines.

---

## 1. Streams vs Collections

```
┌───────────────────────────────────────┐
│ Collection: In-memory Data Storage    │ -> Emphasizes how data is stored
└───────────────────────────────────────┘
                   │
                   ▼ (.stream())
┌───────────────────────────────────────┐
│ Stream: Declarative Pipeline & Compute│ -> Emphasizes how data is transformed
└───────────────────────────────────────┘
```

| Aspect | Collection | Stream |
| :--- | :--- | :--- |
| **Purpose** | Stores and holds data in memory | Computes, transforms, and transfers data |
| **Storage** | Elements exist physically in memory | Does **not** store elements |
| **Mutation** | Modifies underlying elements (add, remove) | Pure & functional: Does not mutate source |
| **Iteration** | **External iteration** (for-each, Iterator) | **Internal iteration** (handled by runtime) |
| **Evaluation** | **Eager** (constructed completely upfront) | **Lazy** (intermediate ops only run when terminal op fires) |
| **Reusability** | Traversed multiple times | **Single-use only** (throws `IllegalStateException` if reused) |

---

## 2. Anatomy of a Stream Pipeline

A Stream pipeline consists of three core phases:

```
[ Source ] ──► [ Intermediate Operations (Lazy) ] ──► [ Terminal Operation (Eager) ]
                 filter() ──► map() ──► sorted()                collect() / forEach()
```

### 1. Creating Streams (Source):
```java
// From a Collection
List<String> list = List.of("apple", "banana", "cherry");
Stream<String> s1 = list.stream();

// From an Array
String[] arr = {"Java", "Kotlin", "Scala"};
Stream<String> s2 = Arrays.stream(arr);

// Direct values or generator
Stream<Integer> s3 = Stream.of(10, 20, 30);
Stream<Integer> infiniteEvens = Stream.iterate(0, n -> n + 2); // Infinite stream
```

---

## 3. Intermediate Operations (Lazy)

Intermediate operations transform a stream into another stream and are **not executed until a terminal operation is invoked**.

| Method | Description |
| :--- | :--- |
| `filter(Predicate<T>)` | Retains elements matching the condition |
| `map(Function<T, R>)` | Transforms each element into another object |
| `flatMap(Function<T, Stream<R>>)` | Flattens nested stream structures (e.g., `List<List<T>>` into `Stream<T>`) |
| `distinct()` | Filters out duplicates using `equals()` |
| `sorted()` / `sorted(Comparator)` | Sorts elements naturally or by custom comparator |
| `limit(long n)` | Truncates the stream to length at most `n` |
| `skip(long n)` | Discards the first `n` elements |
| `peek(Consumer<T>)` | Inspects elements for debugging without modifying them |

### `map()` vs `flatMap()`:
```java
// map() transforms 1 element to 1 element
List<String> words = List.of("hello", "world");
List<Integer> lengths = words.stream().map(String::length).toList();

// flatMap() flattens 1-to-many structures (1 element to Stream)
List<List<String>> nested = List.of(List.of("A", "B"), List.of("C", "D"));
List<String> flattened = nested.stream()
        .flatMap(Collection::stream)
        .toList(); // ["A", "B", "C", "D"]
```

---

## 4. Terminal Operations (Eager)

Terminal operations produce a non-stream result (value, collection) or side-effect and consume the stream.

| Category | Operations |
| :--- | :--- |
| **Accumulators** | `collect(Collector)`, `reduce(BinaryOperator)`, `count()`, `min()`, `max()` |
| **Matchers** | `anyMatch(Predicate)`, `allMatch(Predicate)`, `noneMatch(Predicate)` |
| **Searchers** | `findFirst()`, `findAny()` (both return `Optional<T>`) |
| **Iterators** | `forEach(Consumer)`, `forEachOrdered(Consumer)` |

---

## 5. Collectors & Grouping (`java.util.stream.Collectors`)

```java
List<Employee> employees = getEmployees();

// 1. Grouping by department
Map<String, List<Employee>> byDept = employees.stream()
        .collect(Collectors.groupingBy(Employee::getDepartment));

// 2. Partitioning by condition (Boolean keys)
Map<Boolean, List<Employee>> partitioned = employees.stream()
        .collect(Collectors.partitioningBy(e -> e.getSalary() > 75000));

// 3. Downstream aggregation (Average salary per department)
Map<String, Double> avgSalaryByDept = employees.stream()
        .collect(Collectors.groupingBy(
                Employee::getDepartment,
                Collectors.averagingDouble(Employee::getSalary)
        ));

// 4. Joining strings
String namesCsv = employees.stream()
        .map(Employee::getName)
        .collect(Collectors.joining(", ", "[", "]"));
```

## 6. Parallel Streams

Parallel streams automatically split the workload across CPU cores using the `ForkJoinPool.commonPool()`:

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5, 6, 7, 8);

// Executes operations concurrently across threads
numbers.parallelStream()
        .map(n -> expensiveCalculation(n))
        .forEach(result -> System.out.println(Thread.currentThread().getName() + " -> " + result));
```

> **Performance Caveat**: Parallel streams introduce thread management overhead and synchronisation costs. Use them only for CPU-heavy tasks or massive datasets where elements are stateless and independent.
