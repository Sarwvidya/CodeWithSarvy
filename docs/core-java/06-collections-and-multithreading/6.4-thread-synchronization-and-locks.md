# 6.4 Synchronization, Explicit Locks & Deadlocks

[← Back to Chapter 6: Collections & Multithreading](./index.md)

When multiple threads concurrently read and write shared mutable state, synchronization is mandatory to prevent race conditions and data corruption.

---

## 1. Intrinsic Monitor Locks: `synchronized`

Every Java object possesses an internal **Monitor Lock**. The `synchronized` keyword acquires this monitor:

```java
public class Counter {
    private int count = 0;

    // Synchronized instance method: locks on 'this'
    public synchronized void increment() {
        count++;
    }

    // Synchronized block: finer-grained locking
    public void add(int delta) {
        synchronized (this) {
            count += delta;
        }
    }
}
```

:::tip Prefer Synchronized Blocks over Methods
Synchronizing entire methods increases contention. Synchronize only the minimal critical section where shared state is mutated.
:::

---

## 2. Explicit Locks: `java.util.concurrent.locks.ReentrantLock`

`ReentrantLock` provides advanced locking capabilities unavailable in `synchronized`:
- **Timed Lock Acquisition**: `tryLock(1, TimeUnit.SECONDS)` prevents indefinite thread blocking.
- **Interruptible Lock Wait**: `lockInterruptibly()`.
- **Fairness Policy**: `new ReentrantLock(true)` grants locks in FIFO order to prevent thread starvation.

```java
Lock lock = new ReentrantLock();

lock.lock();
try {
    // Critical Section
    updateSharedResource();
} finally {
    lock.unlock(); // ALWAYS unlock in a finally block!
}
```

---

## 3. Deadlock: Causes & Prevention

A **Deadlock** occurs when two or more threads are blocked forever, each waiting for a lock held by the other.

### The Coffman Conditions for Deadlock:
1. Mutual Exclusion
2. Hold and Wait
3. No Preemption
4. **Circular Wait**

```
Thread 1 holds Lock A, wants Lock B
Thread 2 holds Lock B, wants Lock A
          ──► DEADLOCK! ◄──
```

### Prevention Strategy: Global Lock Ordering
Always acquire locks in an identical global hierarchical sequence across all threads:
```java
// Thread 1 and Thread 2 both acquire Lock A first, then Lock B:
synchronized (lockA) {
    synchronized (lockB) {
        transfer();
    }
}
```
