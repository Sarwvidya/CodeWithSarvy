# 6.5 Thread Pools & ExecutorService

[← Back to Chapter 6: Collections & Multithreading](./index.md)

Manually creating threads (`new Thread().start()`) in enterprise applications creates severe problems: each OS thread allocates a 1MB call stack, and excessive threads cause CPU thrashing due to continuous context-switching.

---

## 1. The Executor Framework Architecture

The `java.util.concurrent` Executor framework separates task submission from task execution using pooled worker threads:

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;

ExecutorService executor = Executors.newFixedThreadPool(10);

Future<String> future = executor.submit(() -> {
    return "Processed payload asynchronously";
});

// Non-blocking retrieval or blocking wait
String result = future.get(); // Blocks until task finishes

executor.shutdown(); // Graceful shutdown
```

---

## 2. Anatomy of `ThreadPoolExecutor`

Behind factory methods like `Executors.newFixedThreadPool`, the core workhorse is `ThreadPoolExecutor`:

```java
ThreadPoolExecutor pool = new ThreadPoolExecutor(
    corePoolSize,          // Minimum live worker threads kept alive
    maximumPoolSize,       // Maximum threads allowed under peak load
    keepAliveTime, unit,   // Idle time before excess threads are destroyed
    new LinkedBlockingQueue<>(1000), // Bounded Work Queue
    new CustomThreadFactory(),       // Custom thread naming
    new ThreadPoolExecutor.CallerRunsPolicy() // Backpressure handler
);
```

### Critical Production Rule: Never Use Unbounded Queues
Avoid `Executors.newCachedThreadPool()` (unbounded thread creation = OOM) and `Executors.newFixedThreadPool()` without custom limits (defaults to an unbounded `LinkedBlockingQueue` that consumes infinite Heap).

---

## 3. Advanced Synchronizers

- **`CountDownLatch`**: Allows one or more threads to wait until a set of operations being performed in other threads completes (`await()`, `countDown()`).
- **`CompletableFuture`**: Asynchronous reactive composition pipeline (`thenApply()`, `thenCompose()`, `exceptionally()`).
