# 6.6 Virtual Threads (Java 21 Project Loom)

[← Back to Chapter 6: Collections & Multithreading](./index.md)

Delivered in **Java 21 LTS** via **Project Loom** (JEP 444), **Virtual Threads** represent the most significant architectural evolution in Java concurrency since Java 1.0.

---

## 1. Platform Threads vs Virtual Threads

```
Platform Thread (1:1 OS Thread)           Virtual Threads (M:N User-mode Threads)
┌────────────────────────┐                ┌──────────┐ ┌──────────┐ ┌──────────┐
│ Java Thread (1MB Stack)│                │ Virtual  │ │ Virtual  │ │ Virtual  │
└───────────┬────────────┘                │ Thread 1 │ │ Thread 2 │ │ Thread N │
            ▼                             └────┬─────┘ └────┬─────┘ └────┬─────┘
┌────────────────────────┐                     └────────────┼────────────┘
│ OS Kernel Thread       │                                  ▼
└────────────────────────┘                      ┌────────────────────────┐
                                                │ Carrier (OS) Thread    │
                                                │ ForkJoinPool Worker    │
                                                └────────────────────────┘
```

| Dimension | Platform (OS) Thread | Virtual Thread (Java 21) |
| :--- | :--- | :--- |
| **Mapping** | 1:1 with OS Kernel Thread | M:N multiplexed onto pool of OS Carrier Threads |
| **Stack Memory** | ~1 MB pre-allocated | **Few hundred bytes** (grows dynamically on Heap) |
| **Concurrency Ceiling** | ~5,000–10,000 threads per server | **1,000,000+ concurrent threads** |
| **Creation Cost** | Heavy (OS system call) | Almost zero (simple Java object allocation) |
| **Blocking IO** | Blocks OS thread completely | **Unmounts** from carrier thread; carrier runs other tasks! |

## 2. Spawning 100,000 Concurrent Virtual Threads

```java
import java.time.Duration;
import java.util.concurrent.Executors;

public class VirtualThreadDemo {
    public static void main(String[] args) {
        // Launches an executor where EVERY task runs on a fresh virtual thread
        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int i = 0; i < 100_000; i++) {
                final int id = i;
                executor.submit(() -> {
                    // Blocking I/O operation! Does NOT block the OS thread!
                    Thread.sleep(Duration.ofSeconds(1));
                    return id;
                });
            }
        } // Auto-closes and waits for all 100k tasks to finish smoothly!
    }
}
```

## 3. The Magic of Continuation & Unmounting

When a Virtual Thread executes a blocking operation (e.g. `Socket.read()`, `Thread.sleep()`, JDBC SQL query):
1. The JVM captures the virtual thread's stack frame as a **Continuation** object on the Java Heap.
2. The virtual thread is **unmounted** from its underlying OS Carrier Thread.
3. The Carrier Thread immediately picks up another ready virtual thread and continues executing CPU instructions.
4. When the OS signals that the I/O event has completed, the JVM **remounts** the continuation back onto an available carrier thread!

:::warning Anti-Pattern: Do Not Pool Virtual Threads
Virtual threads are cheap and disposable. **Never pool virtual threads**. Create a new virtual thread for every incoming request or asynchronous task!
:::
