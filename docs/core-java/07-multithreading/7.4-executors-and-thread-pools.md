# 7.4 Executors & Thread Pools: Architecture, Sizing & Shutdown

[← Back to Chapter 7: Multithreading & Concurrency](./index.md)

Manually allocating `new Thread()` in server applications wastes 1 MB of stack memory per thread and risks `OutOfMemoryError: unable to create native thread`. The Executor Framework manages reusable worker thread pools.

---

## 1. ThreadPoolExecutor Internal Execution Lifecycle

```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    4,                                      // corePoolSize
    16,                                     // maximumPoolSize
    60L, TimeUnit.SECONDS,                  // keepAliveTime for idle surplus threads
    new ArrayBlockingQueue<>(500),          // bounded workQueue
    new ThreadFactoryBuilder().setNameFormat("order-worker-%d").build(),
    new ThreadPoolExecutor.CallerRunsPolicy() // RejectedExecutionHandler
);
```

### The 4-Phase Task Admission Algorithm:
1. If `activeThreads < corePoolSize`: Create a **new worker thread** to execute the incoming task immediately.
2. If `activeThreads >= corePoolSize`: Attempt to queue the task into `workQueue`.
3. If `workQueue` is full and `activeThreads < maximumPoolSize`: Allocate a **new temporary worker thread** up to `maximumPoolSize`.
4. If `workQueue` is full and `activeThreads == maximumPoolSize`: Execute the configured **Rejection Policy** (`AbortPolicy`, `CallerRunsPolicy`, `DiscardPolicy`, `DiscardOldestPolicy`).

---

## 2. Dangers of `Executors` Factory Methods in Production

- **`Executors.newFixedThreadPool(n)`**: Uses an unbounded `LinkedBlockingQueue` (Integer.MAX_VALUE capacity). If tasks arrive faster than workers process them, the heap runs out of memory (`OOM`).
- **`Executors.newCachedThreadPool()`**: Uses `maximumPoolSize = Integer.MAX_VALUE`. Spawns unlimited native OS threads under traffic spikes, freezing the operating system.
- **Production Rule**: Always instantiate `new ThreadPoolExecutor` directly with a **bounded queue** and explicit rejection handler!

---

## 3. Thread Pool Sizing Formulas

- **CPU-Intensive Tasks** (Encryption, Video compression, Complex JSON parsing):
  ```
  Pool Size = CPU Cores + 1
  ```
- **I/O-Intensive Tasks** (Database queries, REST API downstream calls, disk I/O):
  ```
  Pool Size = CPU Cores * (1 + Wait Time / Compute Time)
  ```

---

## 4. Graceful Shutdown Protocol

```java
executor.shutdown(); // Disable new task admissions
try {
    if (!executor.awaitTermination(30, TimeUnit.SECONDS)) {
        executor.shutdownNow(); // Cancel executing tasks via interrupt
        if (!executor.awaitTermination(10, TimeUnit.SECONDS)) {
            System.err.println("Thread pool failed to terminate");
        }
    }
} catch (InterruptedException ie) {
    executor.shutdownNow();
    Thread.currentThread().interrupt();
}
```
